Most radio firmware is written in C. Ferrite, new firmware for the Radtel RT-950 Pro, is written in Rust. We made
that choice on day one, before a single line ran on the radio, and it has shaped almost everything since. Here's
why.

## A radio is a computer with a transmitter attached

The RT-950 Pro has a 120 MHz ARM Cortex-M4 processor, 96 KB of RAM and two radio chips. The firmware decides what
frequency the transmitter keys up on, at what power and for how long. A mistake there isn't a crash on a screen:
it's a carrier on the wrong frequency.

So we wanted the strictest checks we could get, as early as we could get them. Rust's compiler refuses whole
classes of mistakes before the code ever reaches the radio: memory used after it's gone, two tasks changing the
same thing at once, a state the code forgot to handle. Each of those is a bug we never had to find on the bench.

## The slow part of radio work is the bench

Changing the firmware means building an image, flashing it over the programming cable, and testing on a real radio
with a real signal. That round trip takes minutes. A bug the compiler catches costs seconds. Ferrite is built with
the help of AI tools, and Rust's compiler is a strict reviewer for every line, ours or not: if it compiles, a lot
of things are already known to be true.

## The same code runs on the radio and on a computer

Everything above the hardware is plain Rust that builds for a PC as well as for the radio: the screens, the
menus, the APRS decoder, the channel storage, the link to Ferrite Console. That means:

- **Thousands of tests run on a computer** in seconds, on every change, before anything is flashed.
- **The screen recordings on this site** come from the firmware's own drawing code, running on a PC.
- **Ferrite Console** uses the radio's own code, compiled for the browser, to read and write channels, so the two
  can't drift apart.

## No surprises at run time

Ferrite never allocates memory as it runs: everything has its place when the firmware is built, so it can't run
out halfway through a transmission. Code that talks to the hardware directly is fenced off in one small part of
the firmware, each piece with a note saying why it's safe. And if something does go wrong, the radio stops
transmitting and goes to a safe state rather than carrying on.

## Waiting costs almost nothing

Ferrite runs on [Embassy](https://embassy.dev), a Rust framework for small processors where each job (the radio,
the screen, the keys, APRS, GPS) is a task that sleeps until it has something to do. A sleeping processor uses
little power, and Ferrite slows the processor right down while the radio waits. At rest, listening on a quiet
channel, the radio draws about 19 mA: about 107 hours on the stock battery pack.

## What it costs

Rust isn't free. In our first comparison, the same test program came out about a third larger in Rust than in C,
and we keep a close eye on size: some of the processor's flash is fast and some is slow, and code that runs often
has to fit in the fast part. The RT-950 Pro has room for it, and the checks are worth far more to us than the bytes.
