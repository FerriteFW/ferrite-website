Almost every radio firmware out there is written in C. It's the language the chip vendors ship, the one every
example uses, and the one you reach for when there's 96 KB of RAM and no operating system. So naturally, I wrote
Ferrite in Rust.

This wasn't a "rewrite it in Rust" bit. I made the call before a single line of Ferrite ran on the radio, and it
has shaped almost everything since.

## A computer with a transmitter bolted on

Pop the back off a Radtel RT-950 Pro and you'll find an Artery AT32F403A (an ARM Cortex-M4 good for 240 MHz;
Ferrite runs it at up to 120), 96 KB of RAM, two Beken BK4829 radio chips and an SI4732 for broadcast and
shortwave. The firmware on that M4 decides which frequency the transmitter keys up on, at what power, and for how
long.

When that code is wrong, you don't get a crash dialog. You get a carrier on the wrong frequency.

So I wanted the strictest checks I could get, and I wanted them early. Rust's compiler simply refuses a whole pile
of the bugs that bite firmware: memory used after it's gone, two tasks changing the same thing at once, a `match`
that forgot a case. Every one of those is a bug I never had to chase across the bench.

## The bench is the slow part

Changing radio firmware means building an image, flashing it through the stock bootloader over the programming
cable (about 85 seconds), then testing on a real radio with a real signal. That's minutes, every time. A bug the
compiler catches costs seconds.

I also build Ferrite with AI tools helping, and that makes a strict compiler even more valuable. It's a tough
reviewer for every line, mine or not: if it compiles, a lot of things are already true.

## I measured the cost first

I didn't take Rust on faith. My first test image for the radio was C, the usual way. Before going further, I ported
it to Rust feature for feature, same screens and same console, and compared. The Rust build came out about a third
bigger.

That's real, and size has bitten us since. The AT32's flash has a fast part (the first 256 KB, zero wait states)
and a slow part, and anything that runs often has to live in the fast part. Rust copies a generic function into
every caller, and one innocent extra branch in a drawing routine once cost us 18 KB in a single change. We now
check the size map on every change to shared code. Still worth it.

## Same code on the radio and on my desk

Everything above the registers is plain `no_std` Rust that builds for a PC as well as for the radio: the screens,
the menus, the APRS decoder, the channel storage, the link to Ferrite Console. That pays off every single day:

- **Thousands of tests** run on a computer on every change, before anything gets flashed. (Testing gets its own
  post: there's a lot to say.)
- **The screen recordings on this site** are the firmware's own drawing code, running on a PC.
- **Ferrite Console** runs the radio's own code, compiled for the browser, to read and write your channels. The
  two can't drift apart because they're the same code.

## No surprises mid key-up

Ferrite never allocates memory while it runs. No heap, no `alloc`: everything has a home when the image is built,
so it can't run out halfway through a transmission. All the `unsafe` register poking lives in one small corner (the
HAL and start-up), and every block says why it's sound.

And if something does go wrong? A panic compiles to a single trap instruction. The core faults, the fault handler
drops everything into a safe state with the transmitter off, and stops. No limping along with a carrier up.

## Waiting costs almost nothing

Ferrite runs on [Embassy](https://embassy.dev), an async framework for exactly this kind of chip. The radio, the
screen, the keys, APRS and GPS are each a task that sleeps until there's work. While everything's asleep, Ferrite
drops the core from 120 MHz to 24 MHz.

On the bench, sitting on a quiet channel, that's 18.6 mA instead of 64.7 mA with the clock pinned at full speed.
Call it about 107 hours on the stock battery pack. (Resting is the best case: scanning, keys and APRS bring the
clock back up while they run.)
